# puppet-vfx Phase 1 MVP 規格書

> 目標：做一個手機／電腦瀏覽器都能開的「徒手空氣操偶」即時特效濾鏡，揮手就能觸發布袋戲風格特效＋音效，並錄製成短片匯出。

## 1. 技術架構（純前端本地推論）
- **視覺追蹤**：`@mediapipe/tasks-vision`（`HandLandmarker`，`runningMode: "VIDEO"`，`numHands: 2`），取得每隻手 21 個 3D 關鍵點。
- **座標平滑**：速度用「現在 vs 約 80ms 前」的樣本相減（比逐幀相減穩），手掌大小輕度 EMA。M1.2 判斷用原始座標避免延遲；M1.3 刀光軌跡需要時再對指尖加 EMA。
- **特效渲染層**：WebGL 2D 疊加層（**PixiJS**，支援 Additive Blend 發光疊加、序列幀 Sprite Sheet 播放、全畫面震動與殘影）。
- **音效引擎**：Web Audio API 預載短音效（聚氣嗡鳴、劍氣破空、掌風爆破、古風鑼鼓點），並混流進錄影輸出。
- **錄影匯出**：`canvas.captureStream(30)` + Web Audio `MediaStreamAudioDestinationNode` → `MediaRecorder`（自動偵測瀏覽器支援 `video/mp4` 或 `video/webm`）。
- **畫面合成**：相機畫面以影片貼圖放進 PixiJS 舞台最底層，骨架與特效疊在同一個容器（座標＝影片像素）。錄影錄的是這張 canvas，所以「人＋特效」會一起錄進去。
- **鏡像**：前鏡頭預設左右翻轉（照鏡子習慣），翻轉只做在外層容器一次，特效座標不用另外翻。後鏡頭（`?cam=environment`）不翻。
- **啟動按鈕**：一律先按「開始」才開相機與音效（手機瀏覽器通常要使用者先點一下才能播放音效）。
- **本機資源**：MediaPipe wasm 與手部模型放在 `web/public/`，執行時不連外部 CDN。

## 2. 招式設計：一手戲偶＋一手技能（2026-11-23 老闆改）

原設計把招式綁在「老闆的手」上，但這是布袋戲：手應該是戲偶。改成**一手擺戲偶姿勢（角色），另一手比技能手勢，特效從戲偶身上發出**。

**老闆 2026-11-23 的決定**
- 特效從戲偶身上發出（技能手像遙控器）。
- 戲偶手：食指當頭，拇指與中指當兩臂，無名指和小指彎起來（老闆 2026-11-23 看紀錄確認的實際姿勢；原本寫的「三指併成一臂」作廢）。
- 必須有戲偶才能出招（畫面上沒有戲偶手時，技能手怎麼揮都不觸發）。
- 聚氣先拿掉；護體氣場延後。

| 招式 | 觸發條件 | 特效起點 | 視覺特效（M1.3） | 音效 |
| :--- | :--- | :--- | :--- | :--- |
| **推掌（Palm Strike）** | 戲偶在＋技能手張掌、手掌變大速度 `>= 門檻`（往鏡頭推），冷卻 `0.8s` | 戲偶身體，**往戲偶面向打**（掌心那面投影到畫面；正對鏡頭時往遠離技能手那側） | 衝擊波紋＋水墨氣浪＋畫面微震 | 重擊氣爆聲 |
| **劍指斬（Sword Slash）** | 戲偶在＋技能手食中指併攏伸直、指尖速度 `>= 門檻`，冷卻 `0.5s` | 戲偶靠技能手那側的手臂，方向＝劃的方向 | 刀光拖尾＋火花 | 劍氣破空聲 |
| ~~聚氣~~ | 拿掉（老闆 2026-11-23） | | | |
| ~~護體氣場~~ | 延後 | | | |

**判斷方式**
- 長度一律以「手掌長」（腕 `0` → 中指根 `9`）為單位，速度＝手掌長／秒，手離鏡頭遠近不影響門檻。
- 手指伸直：指尖到腕 > 第二關節到腕 × 倍數。張掌＝四指伸直；劍指＝食中伸直、無名小指彎、兩指尖靠近。
- **戲偶鎖定（老闆 2026-11-23）**：認到戲偶手一次後，這隻手還在畫面裡就一直是戲偶（翻手、轉身都不掉），手離開畫面超過 0.3 秒才收偶。原因：老闆紀錄實測，戲偶手正面 97% 認得到，翻面 0%（模型把食指、中指也看成彎的）。用位置追蹤同一隻手（翻手時左右手標籤會跳），戲偶不見的期間技能手經過原位也不會搶走戲偶。代價：手還在畫面上、只是沒擺戲偶時，另一隻手照樣能出招（舊錄製的亂動步驟多 1 次誤判）。
- 戲偶手：食指、中指伸直，無名指、小指彎；食中分開角度 ≥ 15°、食指與拇指分開 ≥ 12°（老闆實測都約 24°）；拇指和中指在食指兩側（排除比 YA）；和劍指互斥（劍指是兩指併攏）。短暫認不到（預設 0.3 秒內）仍算戲偶在。
- 「往鏡頭推」看手掌大小的變化率：**2026-11-23 老闆 Mac 實測**腕 z 一直約 1e-7（≈0，模型 z 以手腕為原點），不能用。
- **防誤判（2026-11-23 依老闆引導錄製調整）**：
  - 劍指斬：最近 0.25 秒內劍指要占 ≥ 25%（揮手時手指一閃而過的劍指不算）。
  - 推掌：最近 0.25 秒內張掌要占 ≥ 80%；「揮動量」（指尖相對掌心的移動，扣掉平移與放大）≤ 2.5；掌心平移 ≤ 8 手掌長／秒。真推掌實測揮動量 ≤ 1.3、平移 ≤ 4。
  - 直劈（劍指往鏡頭劈）：劈到最快時手指正對鏡頭，手部模型會把手指估成彎的（紀錄實測：指鏡頭的食指彎曲角中位數 56～102°，和握拳分不開），單看那幀認不出劍指。改成「最近 0.25 秒有穩定劍指＋這幀是兩指併攏、指向鏡頭（`pointToward` ≥ 0.6）」也算。只放寬到「不是張掌」會把劈完收手變握拳誤算，已排除。
  - **直劈跟丟版（2026-11-23 老闆第三次引導錄製）**：實測往下劈時畫面糊掉，手部模型**整個跟丟 0.1～0.3 秒**，手再出現時已在下方；原本出的 7 招全是「劈完把手舉回來」那一下。新增：技能手上一幀還在、最近 0.25 秒劍指（含指向鏡頭）≥ 50%、指尖往下 ≥ 3 手掌長／秒，這一幀突然不見 → 算一次往下的劍指斬（不用等手出現，沒有延遲）。手往下跟丟後 0.8 秒內「往上」的劍指斬不算（舉手回來）。重播：直劈步驟從 7 次全往上 → 7 次往下＋3 次往上；橫劃、推掌、亂動步驟結果不變，舊錄製也不變（誤判仍 1）。
  - 成效（重播老闆第二次引導錄製）：正確 10/10，誤判 11 → 1。剩下 1 次是「另一手亂晃」時的一個動作，數值和真推掌分不開。
- 門檻都在 `web/src/fsm.js` 的 `DEFAULTS`，全部暫定，老闆實機試揮後才定案。測試頁右上「⚙ 調門檻」可即時調。
- 重播工具：`node scripts/replay.mjs logs/<檔名>.jsonl [第幾次引導] ['{"門檻":值}']`，用試揮紀錄比較不同門檻的正確／誤判次數（在 `web/` 下執行）。
- 單元測試：`web/tests/`（合成手勢，`node --test tests/`）。

**試揮紀錄**：`npm run dev` 時每一幀的關鍵點、特徵、狀態、招式自動存到 `web/logs/<開頁時間>.jsonl`（只有數字、不含影像）。老闆按「▶ 引導錄製」照提示做（自動貼標籤），或在下方標籤列按數字鍵；判斷錯了按 X；Claude 讀紀錄分析，老闆不用逐條回報。**頁面要在最前面**，切到別的視窗時瀏覽器會暫停偵測（紀錄會出現空白）。
